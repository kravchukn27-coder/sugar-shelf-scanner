# Промт: переделать экран пейвола в Sugar Shelf Scanner

Скопируй всё, что ниже разделителя, и отдай другому ИИ. Текст самодостаточный.

---

## Задача

Переделай экран пейвола в мобильном веб-приложении Sugar Shelf Scanner.
Меняем **только внешний вид и текст** этого экрана. Механику оплаты не трогаем —
она написана, протестирована и уже работает на проде.

Репозиторий: `sugar-shelf-scanner` (Next.js 15 App Router, React 19,
TypeScript 5.8).

## Что это за продукт

Мобильное веб-демо. Человек наводит камеру на полку в магазине, Gemini
распознаёт упаковки, приложение показывает карточки с содержанием сахара.

Идёт тест монетизации: три бесплатных скана на браузер, потом стена. Дальше —
$2.99 разово за 7 дней безлимита, оплата через Stripe Payment Link, подписки
нет. Трафик покупается в Facebook и Instagram, рынок американский. Значит
экран почти всегда открывается **на телефоне, во встроенном браузере Instagram,
холодным человеком, который видит продукт впервые**.

## Позиционирование — уже решено, не менять

Сейчас на стене написано «вы истратили бесплатные сканы, купите безлимит на
7 дней». Это продажа функции. Продакт решила продавать другое:

> **Неделя как эксперимент над собой.** Человек платит не за инструмент, а за
> то, чтобы узнать правду про свою обычную корзину: сколько сахара на самом
> деле в том, что он покупает каждую неделю не задумываясь.

Тон: снижаем тревожность, а не нагнетаем. Аудитория — люди, которые уже
переживают из-за сахара. Не пугать, не стыдить, не давить срочностью.

**Важное ограничение честности.** Приложение ничего не копит: ни истории, ни
аккаунтов, телеметрия принципиально обезличена. Итога недели не существует —
каждый скан отдельное маленькое открытие. Поэтому нельзя обещать отчёт, сводку,
«ваши результаты за неделю» или любой накопленный результат. Обещание — сам
процесс и то, что человек узнаёт по ходу.

## Файлы

Меняй только эти два:

- `src/app/paywall.tsx`
- `src/app/paywall.module.css`

Не трогай `src/app/page.tsx`, `src/lib/access/**`, `src/app/api/access/**`.

## Контракт компонента — сохранить дословно

Компонент чисто презентационный: он ничего не знает ни про Stripe, ни про
хранилище, ни про телеметрию. Всё поведение приходит пропсами. Экспорты и типы
менять нельзя, иначе сломается вызов в `page.tsx`.

```tsx
export type PaywallRestoreState = "idle" | "working" | "not_found" | "error";

export type PaywallProps = {
  /** False when this deployment has no Payment Link configured. */
  checkoutAvailable: boolean;
  restoreState: PaywallRestoreState;
  onCheckout: () => void;
  onRestore: (email: string) => void;
  onClose: () => void;
};

export default function Paywall(props: PaywallProps) { ... }
```

Вызывается так (эту строку не менять):

```tsx
<Paywall checkoutAvailable={checkoutUrl.length > 0} restoreState={restoreState}
  onCheckout={startCheckout} onRestore={(email) => void restoreAccess(email)}
  onClose={() => setPaywallOpen(false)} />
```

## Что на экране должно остаться обязательно

1. **Кнопка покупки.** Вызывает `onCheckout()`. Должна быть `disabled`, когда
   `checkoutAvailable === false`, и тогда рядом текст, что оплата сейчас
   недоступна.
2. **Цена $2.99 и слово про отсутствие подписки.** На холодном трафике из Meta
   главное возражение — «спишут потом». Снять его явно. Валюта только доллары,
   знака евро быть не должно нигде.
3. **Восстановление доступа.** Ссылка-раскрывашка с текстом ровно
   `Already paid on another browser?`, за ней форма с полем почты и кнопкой
   `Restore access`, вызывающей `onRestore(email)`. Это не украшение: человек,
   заплативший во встроенном браузере Instagram и открывший ссылку позже в
   Safari, приходит с пустым хранилищем, и это единственный способ вернуть
   оплаченное. Поле — `type="email"`, `inputMode="email"`,
   `autoComplete="email"`, `maxLength={254}`, размер шрифта **не меньше 16px**
   (иначе iOS Safari зумит при фокусе).
4. **Сообщения о ходе восстановления** по `restoreState`, в элементе с
   `role="status"`, иначе незрячий человек не узнает, получилось или нет:
   - `working` → `Looking for your access…`
   - `not_found` → `No active access for that address. Check the address you paid with.`
   - `error` → `Couldn’t check that right now. Try again in a moment.`
   Кнопка отправки `disabled` при `working`.
5. **Кнопка закрытия** с `aria-label="Close"`, вызывает `onClose()`.
6. **Дисклеймер** `This is a demo. Always check the package label before a dietary decision.`
7. Контейнер: `role="dialog"`, `aria-modal="true"`, осмысленный `aria-label`.

## Чего на экране быть НЕ должно

- **Счётчика оставшихся бесплатных сканов.** Решение принято сознательно:
  видимый счётчик превращает пробу в экономию, а тесту нужно обратное.
- Любого обещания отчёта, сводки или накопленного итога недели (см. выше).
- Выдуманной статистики. Если хочется написать «большинство ошибается насчёт
  трёх вещей» — такую цифру надо чем-то подтвердить, иначе не писать.
- Таймеров, обратного отсчёта, «осталось 2 места» и прочей ложной срочности.

## Фирменный стиль

Взят из бренд-бука Sugar.no (`design/reference/sugar-no-brand-book.html`).

Палитра:

| Роль | Значение |
| --- | --- |
| Void — фон камеры и оверлеев | `#0A0A0C` |
| Ink — основной текст, заливка главной кнопки | `#17171B`, кнопка `#131215` |
| Paper — карточки и шторки | `#FFFFFF` |
| **Honey — только для платного предложения** | `#F6D98A → #ECB548` |
| Ember — только активная вкладка в таб-баре | `#FF5A45` |
| Signal Blue — действия «снять/приложить» | `#2F6FEF` |
| Vital Green — витальность | `#4FCE78` |
| Slate — вторичный текст | `#726D7C` |
| Светлый текст на тёмном | `#F2F1F6`, приглушённый `#CFCCD8`, мелкий `#A19CAD` |

**Текущий экран красит кнопку покупки в Ember — это ошибка.** По бренд-буку
Ember закреплён за активной вкладкой, а за платным предложением закреплён
Honey. Исправить.

Типографика: один скруглённый гротеск, шрифтовой стек уже стоит в
`globals.css` — `ui-rounded, "SF Pro Rounded", -apple-system` с веб-запасным
`Nunito`. Иерархию держит насыщенность, а не размер; всё в диапазоне 700–900.
Дисплейный размер 34 при весе 800 и трекинге −1.5%. Заголовок экрана 27/800.
Заголовок карточки 19/800. Тело 15/600. Мелкий текст 13/700.

Радиусы: 8 чип · 13 иконка · 18 строка · 24 карточка · 30 шторка · пилюля.
Отступы: 4 · 8 · 12 · 16 · 22 · 28.

Кнопки, три семейства, на одной поверхности не смешивать: сплошная чернильная
пилюля для единственного главного действия, высотой около 46; синяя — для
«снять/приложить»; контурная — для вторичного подтверждения.

Экран должен читаться как часть Sugar.no, а не как чужая платёжная вставка.

## Направление

Выбрано направление «Эксперимент»: заголовок задаёт вопрос про самого человека,
вторая строка даёт понятный протокол на неделю. Примерно так по смыслу
(формулировки можно и нужно улучшать, английский — язык интерфейса):

- Заголовок: *What's really in your basket?*
- Подзаголовок: *For one week, scan everything you'd normally buy.*
- Кнопка: *Start my week*
- Под кнопкой: *$2.99 once · 7 days · no subscription*

Предложи 2–3 варианта текста в этом направлении, прежде чем остановиться на
одном. Весь текст интерфейса — английский.

## Технические ограничения

- **Никаких новых зависимостей.** Ни анимационных библиотек, ни UI-китов, ни
  иконочных пакетов. В проекте `npm test` — это `tsx --test` по
  `src/**/*.test.ts`, DOM-раннера нет, тесты React-компонентов писать нельзя и
  не нужно.
- Стили — только в `src/app/paywall.module.css`, CSS-модулем. Не подключать
  Tailwind, не писать инлайновые стили пачками.
- Учитывать безопасные зоны: `env(safe-area-inset-top)` и
  `env(safe-area-inset-bottom)`. Экран открывается в полноэкранном режиме на
  айфонах с чёлкой.
- Комментарии в коде — английские, и объясняющие «почему», а не «что».

## Как проверить

1. `npm run typecheck` — без ошибок.
2. `npm run build` — чистая сборка.
3. Посмотреть глазами при ширине **375×812** (iPhone), в тёмной среде. Проверить:
   - главная кнопка не уезжает под безопасную зону снизу;
   - форма восстановления раскрывается и поле не зумит экран при фокусе;
   - при `checkoutAvailable={false}` кнопка выключена и это объяснено;
   - все четыре состояния `restoreState` выглядят осмысленно.
4. Контраст текста к фону не ниже 4.5:1. На предыдущей версии этого экрана уже
   была ошибка: светлый текст положили на светлый фон, получилось 1.2:1.
